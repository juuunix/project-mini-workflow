# 미니 워크플로우 엔진

노드를 그래프로 연결해 실행하는 워크플로우 엔진입니다. 같은 엔진으로 성격이 다른 워크플로우 두 개를 실행하고, 실행된 노드마다 결과를 출력합니다. 에이전트 워크플로우는 LLM이 필요한 도구(문서 검색, 날짜 조회)를 골라 답하고, 문서 이력 워크플로우는 LLM 없이 문서의 메타데이터로 주제별 개정 이력을 정리합니다. 그래프 실행에는 LangGraph를 쓰고, LLM은 정해진 규칙으로 답하는 가짜 구현이라 API 키가 필요 없습니다.

## 드리고 싶은 말

먼저 이번 과제 전형을 준비해 주셔서 감사합니다. 원래는 없던 전형을 새로 마련해 주셨다고 들었습니다. 그 밖에도 면접 결과를 빠르게 알려 주시는 등 진행 내내 제 사정을 많이 배려해 주셔서 감사했습니다. 처음 진행하시는 전형인 만큼, 앞으로의 전형에 참고하실 자료가 될 수 있도록 최선을 다했습니다. 구현하면서 고민이 컸던 부분과 그때 내린 판단을 몇 가지 남겨 드립니다.

가장 큰 고민은 RAG였습니다. LLM은 가짜 구현을, 문서는 직접 준비한 자료를, 검색은 키워드와 임베딩 중 어느 방식이든 허용해 주셨습니다. 이 조건을 보고, 이 과제에서 확인하시려는 것은 검색 성능보다, RAG를 포함한 워크플로우 전체를 AI와 함께 설계하고 구현해 가는 과정이라고 판단했습니다. 그래서 검색은 BM25 키워드 검색을 골랐습니다. 임베딩 모델을 내려받거나 실행할 필요가 없어 설치와 실행 환경을 단순하게 유지할 수 있기 때문입니다. 문서는 공개 자료를 가져와 정리하는 방법도 검토했습니다. 실무에서는 다양한 문서를 다루는 만큼, 검색 대상으로 넣기 전에 문서 번호, 상태, 시행일 같은 메타데이터를 갖추는 단계가 있을 것이라고 생각합니다. 그래서 그렇게 정리된 상태를 전제로 문서를 직접 만들었습니다. 실제에 가까운 데이터 확보 후 전처리에 쓸 시간은 노드와 흐름을 만드는 데 쓰는 것이 맞다고 판단했습니다.

이 판단을 바탕으로 만들다 보니, 지금의 RAG는 검색 성능보다는 정해 둔 시나리오와 규칙대로 움직이는 정적인 도구에 가까워졌습니다. 문서 규모가 작아 전체를 메모리에 올려 두고 찾고, 관련 문서 판정에도 "질의의 단어가 제목에 있는가"처럼 이 데이터에 기댄 규칙을 더했습니다. 만약 이 판단이 과제의 의도와 달랐다면, 실제에 더 가까운 규모의 문서를 다룰 수 있는 라이브러리를 고르고, 문서의 종류에 따라 청크 단위를 달리하고, 키워드 검색에 임베딩 검색을 더하는 데 시간을 더 썼어야 했다고 생각합니다. 과제 전형을 통과하게 된다면, 면접에서 이 부분을 함께 이야기 나눌 수 있으면 좋겠습니다.

구조도 한 번 크게 바꿨습니다. 처음에는 과제의 요구사항을 바탕으로, LLM이 도구(문서 검색, 날짜 조회)를 골라 답하는 에이전트 그래프 하나로 만들었습니다. 요구사항에 LLM이 있으니 에이전트 루프를 만들어야 한다는 고정관념이 조금 있었던 것 같습니다. 이후 과제 안내문을 다시 점검하면서, 요구하시는 것은 n8n처럼 여러 워크플로우를 같은 엔진으로 실행하는 구조에 가깝다고 판단해 리팩터링했습니다. 다만 n8n처럼 노드를 자유롭게 붙이고 빼는 수준은 아닙니다. 워크플로우는 코드로 조립하고, 에이전트에 도구 노드를 더하려면 가짜 LLM의 규칙도 함께 고쳐야 합니다. 기회가 된다면 과제의 의도에 대해서도 의견을 나눠 볼 수 있으면 즐거울 것 같습니다.

현재 저장소는 공개되어 있지만, 회사의 과제 내용이 담겨 있는 만큼 전형이 끝나면 비공개로 전환하거나 삭제하겠습니다.

다시 한번 여러 가지로 신경 써 주셔서 감사합니다. 이번 과제를 진행하며 많이 배울 수 있었습니다.

## 실행 방법

필요한 것: [Docker Desktop](https://www.docker.com/products/docker-desktop/)

명령은 저장소 폴더에서 실행합니다. Windows 11의 PowerShell과 명령 프롬프트에서 같은 명령을 씁니다.

설치(이미지 만들기, 처음 한 번):

```
docker build -t mini-workflow .
```

Python 3.13과 필요한 패키지가 이미지 안에 설치됩니다.

시연:

```
docker run --rm -t mini-workflow
```

테스트:

```
docker run --rm mini-workflow pytest
```

## 시연 내용

시연은 에이전트 워크플로우로 질문 6개를, 문서 이력 워크플로우로 주제 2개를 차례로 실행합니다. 모두 실행한 뒤 시나리오마다 입력, 노드 실행 표, 답변을 출력합니다. 에이전트의 마지막 질문은 재시도를 기다리느라 몇 초 걸립니다.

### 에이전트 워크플로우

| 질문 | 실행 경로 | 보여 주는 것 |
| --- | --- | --- |
| 안녕하세요 | LLM | 도구가 필요 없는 질문은 바로 답하고 끝남 |
| 오늘 날짜 알려줘 | LLM → 날짜 조회 → LLM | 검색과 다른 종류의 도구 노드 |
| 연차휴가 이월은 최대 며칠까지 가능한지 찾아줘 | LLM → 문서 검색 → LLM | 현행 문서에서 찾은 본문으로 답함 |
| 웰니스 포인트는 언제 폐지됐는지 찾아줘 | LLM → 문서 검색 → LLM → 문서 검색 → LLM | 현행 문서에 없어 보관 문서에서 다시 찾음 |
| 사내 동호회 가입 방법 찾아줘 | LLM → 문서 검색 → LLM → 문서 검색 → LLM | 현행 문서와 보관 문서 모두에 없어 찾지 못했다고 답함 |
| 재택근무 운영 지침 찾아줘 | LLM → 문서 검색 → LLM(실패) → 오류 처리 → 오류 안내 | LLM이 3번 시도 끝에 실패하고 오류 안내로 끝남 |

### 문서 이력 워크플로우

| 주제 | 실행 경로 | 보여 주는 것 |
| --- | --- | --- |
| 배포 | 문서 찾기 → 메타데이터 읽기 ×3 → 정리 결과 작성 | 현행 문서와 보관 문서를 찾아 문서마다 메타데이터를 읽고, 문서 번호별 개정 이력과 지금 따라야 할 문서를 정리함 |
| 동호회 | 문서 찾기 → 문서 없음 안내 | 찾은 문서가 없어 다른 경로로 끝남 |

## 문서 데이터

출처: AI를 사용해 만든 문서입니다.

검색 대상 문서는 `data/docs/`에 있는 마크다운 문서 30개(UTF-8, 약 120KB)입니다. 가상의 회사 "주식회사 모음소프트"와 그 서비스 "모음보드"의 사내 규정, 기술·운영 문서, 고객 안내 문서이며, 실제 회사나 개인의 정보는 담겨 있지 않습니다.

- `data/docs/current/`: 지금 유효한 현행 문서 15개
- `data/docs/archive/`: 개정되었거나 폐지되어 보관 처리된 문서 15개
