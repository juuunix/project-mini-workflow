# 요구사항

## 목적

개별 작업을 노드로 정의하고 그래프로 연결해 실행할 수 있도록 한다. 각 노드의 결과를 후속 노드에 전달하고, 실행 상태에 따라 경로를 분기하거나 작업을 반복할 수 있도록 한다. 문서 검색을 노드로 제공해 검색 결과를 후속 작업에서 활용할 수 있도록 한다.

## 기능 요구사항

### FR-01 그래프 실행

- 요구사항: 엔진은 노드와 노드 사이의 연결을 정의한 그래프를 받아 시작 노드부터 실행한다.
- 충족 기준: `A → B → C`로 연결된 그래프를 `A`에서 시작하면 실행 기록에 `[A, B, C]`가 순서대로 남는다. 마지막 노드 `C`의 실행이 끝나면 엔진은 해당 워크플로우의 성공 결과를 반환한다.

### FR-02 실행 결과 출력

- 요구사항: 시연은 실행된 각 노드의 이름과 결과 요약을 실행 순서대로 출력한다.
- 충족 기준: 시연 출력을 실제 노드 실행 순서와 대조한다. 반복 실행과 실패를 포함해 각 실행에 대응하는 노드 이름과 결과 요약이 한 줄 이상 출력된다.

### FR-03 조건 분기

- 요구사항: 엔진은 입력이나 실행 상태에 따라 다음 실행 경로를 선택할 수 있다.
- 충족 기준: 서로 다른 경로가 예상되는 입력을 두 건 이상 시연한다. 각 입력의 실행 경로가 예상과 일치하고, 그중 두 경로 이상이 서로 다름을 출력에서 확인할 수 있다.

### FR-04 반복 실행

- 요구사항: 엔진은 종료 조건이 충족될 때까지 앞서 실행한 노드를 다시 실행할 수 있다. 정해진 횟수까지 반복해도 종료 조건이 충족되지 않으면 엔진은 실행을 중단하고 실패 결과를 반환한다.
- 충족 기준: 반복이 필요한 입력을 시연한다. 한 번의 워크플로우 실행에서 같은 노드가 두 번 이상 실행되고, 종료 조건이 충족되어 실행이 끝난 것을 출력에서 확인할 수 있다. 종료 조건이 충족되지 않는 그래프를 자동 테스트로 실행하면, 정해진 횟수만큼만 반복한 뒤 반복 상한 초과를 원인으로 하는 실패 결과가 반환된다.

### FR-05 상태 전달

- 요구사항: 후속 노드는 앞 노드가 생성한 값을 사용할 수 있다.
- 충족 기준: 앞 노드가 알려진 값을 생성하는 워크플로우를 실행한다. 앞 노드가 생성한 값과 후속 노드가 그 값을 사용해 얻은 예상 결과를 시연 출력에서 확인할 수 있다.

### FR-06 노드 실패 처리

- 요구사항: 노드 실패는 노드가 결과를 반환하지 못하고 예외를 발생시킨 경우를 말한다. 검색 결과 없음처럼 노드가 정상적으로 반환한 결과는 실패가 아니며, 분기 조건으로 다룬다. 노드에 재시도가 지정되어 있으면 정해진 횟수까지 다시 실행하고, 그래도 실패하면 실패로 처리한다. 노드가 실패하면 엔진은 실패한 노드 이름과 실패 원인을 기록한다. 그 노드에 오류 처리 노드가 지정되어 있으면 실패 내용을 오류 처리 노드에 전달해 실행하고, 지정되어 있지 않으면 실행을 중단하고 실패 결과를 반환한다. 어느 경우에도 실패한 노드의 정상 결과를 전제로 하는 실행은 이어지지 않는다. 오류 처리 노드는 기록된 실패 원인을 사용할 수 있다. 오류 처리 노드까지 실행되고 끝난 실행은 성공으로 끝나며, 실행 기록에는 실패한 노드와 처리 결과가 남는다. 시연은 실패한 노드 이름과 엔진의 처리 결과를 출력한다.
- 충족 기준: 오류 처리 노드가 지정된 노드가 실패하는 시연을 실행한다. 출력에 실패한 노드 이름, 실패 원인, 오류 처리 노드로 이동했다는 표시가 나타난다. 오류 처리 노드의 결과 요약에는 실패 원인이 반영되어 있다. 오류 처리 노드가 지정되지 않은 노드가 실패하는 그래프를 자동 테스트로 실행하면, 후속 노드는 실행되지 않고 실패한 노드 이름과 실패 원인을 담은 실패 결과가 반환된다. 시연 명령은 처리되지 않은 예외 없이 끝까지 실행된다. 한 워크플로우 실행이 실패해도 시연은 다음 입력을 계속 실행한다.

### FR-07 노드 확장

- 요구사항: 엔진이 실행할 새 노드 타입을 추가할 수 있다.
- 충족 기준: 엔진 모듈에 없는 새 노드 타입을 정의해 그래프에 연결하면, 엔진 모듈을 변경하지 않아도 실행된다. 시연에서는 문서 검색 노드를 포함해 서로 다른 노드 타입이 두 종류 이상 실행된다.

### FR-08 RAG 문서 검색

- 요구사항: 문서 검색 노드는 질의를 받아 저장소에 포함된 문서를 검색하고, 검색 결과를 반환한다.
- 충족 기준: 검색 결과가 예상되는 질의로 시연을 실행한다. 엔진이 실행한 문서 검색 노드가 해당 문서를 반환하고, 시연 출력에 질의와 해당 문서의 제목 또는 식별자가 표시된다.

### FR-09 통합 시연

- 요구사항: 시연 워크플로우는 문서 검색 노드, 조건 분기, 반복 실행을 모두 포함하고 끝까지 실행된다.
- 충족 기준: 시연을 실행한다. 하나의 워크플로우 실행 안에서 문서 검색 노드 실행, 조건 분기, 같은 노드의 반복 실행이 모두 일어나고, 해당 워크플로우 실행이 종료된 것을 출력에서 확인할 수 있다.

## 비기능 요구사항

### NFR-01 실행 환경 호환성

- 요구사항: Python 3.11 또는 3.13 중 하나를 선택해 README에 명시한다. 시연과 테스트는 Windows 11 Pro 64비트에서 실행할 수 있어야 하며, 셸 스크립트(`.sh`)나 `make`에 의존하지 않는다.
- 충족 기준: Windows 11 Pro 64비트에서 Docker 이미지 또는 uv 환경 중 하나를 준비한 뒤, 시연과 자동 테스트를 각각 명령 하나로 실행할 수 있다. 설치와 실행 과정에서 셸 스크립트나 `make`를 사용하지 않는다.

### NFR-02 실행 재현성

- 요구사항: 시연과 테스트는 API 키 없이 실행할 수 있어야 하며, 시연 중 문서 데이터를 외부에서 내려받지 않는다.
- 충족 기준: 설치가 끝난 환경에서 API 키를 설정하지 않고 시연과 테스트를 실행할 수 있다. 시연은 저장소에 포함된 문서로 검색 결과를 반환하며 외부에서 문서를 내려받지 않는다.

### NFR-03 문서 데이터 구성

- 요구사항: UTF-8로 인코딩한 마크다운 또는 일반 텍스트 문서 10개 이상을 저장소 내 한 디렉터리에 포함한다. 전체 용량은 5 MB 이하로 제한한다. 개인정보와 재직 중인 회사의 내부 자료는 포함하지 않는다.
- 충족 기준: 저장소 내 문서 디렉터리에 UTF-8로 읽을 수 있는 .md 또는 .txt 문서가 10개 이상 있고, 전체 용량이 5 MB 이하인지 확인한다. 문서 출처가 README에 기록되어 있는지 확인한다. 문서에 개인정보나 재직 중인 회사의 내부 자료가 포함되어 있지 않은지 확인한다.

### NFR-04 자동 검증

- 요구사항: 직접 작성한 자동 테스트를 저장소에 포함한다.
- 충족 기준: README의 테스트 명령 하나를 실행하면 직접 작성한 자동 테스트가 실행되고, 테스트의 통과 또는 실패를 확인할 수 있다.

### NFR-05 출력 가독성

- 요구사항: 시연 출력은 성공, 실패, 분기, 반복 같은 실행 결과를 글자로 표시한다. 색은 이 표시를 강조하는 데만 사용한다.
- 충족 기준: 색이 표시되지 않는 환경에서도 시연 출력에서 각 노드의 성공 또는 실패, 선택된 분기 경로, 반복 횟수를 글자로 확인할 수 있다.
