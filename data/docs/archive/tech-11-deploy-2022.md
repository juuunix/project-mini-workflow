# 서비스 배포 절차 (2022년판)

- 문서 번호: TEC-002
- 상태: 보관 (개정 전)
- 시행일: 2022-03-01
- 폐지일 또는 개정일: 2025-04-30

> 이 문서는 과제 시연을 위해 AI로 생성한 가상 회사의 문서입니다.

> 보관 안내: 이 문서는 2025년 5월 1일 개정으로 효력을 잃은 이전 판이다. 배포 방식, 배포 가능 시간, 롤백 기준이 현행과 다르다.

## 1. 목적

이 문서는 모음보드 서비스의 운영 배포 절차를 정한다.

## 2. 배포 원칙

1. 운영 배포는 `release` 브랜치에서 태그를 생성한 커밋을 대상으로 한다.
2. 배포는 블루그린 방식으로 진행하며, 새 환경 준비 후 트래픽을 한 번에 전환한다.
3. 배포 이력은 배포 담당자가 배포 기록 문서에 직접 작성한다.

## 3. 배포 가능 시간

| 구분 | 기준 |
| --- | --- |
| 정기 배포 | 월요일 ~ 목요일 14:00 ~ 17:00 |
| 배포 금지 | 금요일, 공휴일 전날 |
| 긴급 배포 | 플랫폼운영팀 책임자 승인 시 가능 |

## 4. 배포 전 점검

1. 풀 리퀘스트는 리뷰어 1명 이상의 승인을 받아야 병합할 수 있다.
2. 단위 테스트가 통과해야 한다. 통합 테스트는 주 1회 일괄 실행한다.
3. 데이터베이스 스키마 변경은 배포 전날까지 플랫폼운영팀에 알린다.
4. 스테이징 환경 점검은 권장 사항으로 한다.

## 5. 배포 진행

| 순서 | 작업 | 담당 |
| --- | --- | --- |
| 1 | 대기 환경(그린)에 새 버전 설치 | 배포 담당자 |
| 2 | 대기 환경 상태 점검 (헬스 체크) | 배포 담당자 |
| 3 | 로드밸런서 트래픽 100% 전환 | 플랫폼운영팀 |
| 4 | 20분간 지표 관찰 | 배포 담당자 |
| 5 | 이전 환경(블루) 1시간 유지 후 정리 | 플랫폼운영팀 |

## 6. 롤백 기준

1. 전환 후 오류율이 3%를 넘으면 롤백한다.
2. 롤백은 로드밸런서를 이전 환경으로 되돌리는 방식으로 하며, 결정 후 15분 이내에 완료한다.
3. 이전 환경을 정리한 뒤에는 직전 태그를 다시 배포하는 방식으로 롤백한다.

## 7. 배포 후 조치

1. 배포 담당자는 배포 결과를 배포 채널에 공유한다.
2. 릴리스 노트는 배포 주간 금요일까지 사내 위키에 게시한다.

## 8. 배포 기록 문서 작성 요령

배포 담당자는 배포 기록 문서에 배포 일시, 대상 태그, 승인자, 전환 시각, 관찰 결과, 이전 환경 정리 시각을 적는다. 롤백이 있었던 경우 롤백 사유와 완료 시각을 함께 적는다. 배포 기록 문서는 월말에 플랫폼운영팀이 검토하였다.

## 9. 배포 공지

배포 담당자는 배포 하루 전 오후까지 배포 채널에 배포 예정 시각과 주요 변경 사항을 공지하였다. 고객에게 보이는 화면이 바뀌는 경우에는 고객지원팀에도 같은 내용을 메일로 전달하였다. 공지 없이 진행한 배포는 월말 검토에서 따로 표시하였다.
