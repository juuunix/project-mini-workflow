# 운영 환경 접근 권한 관리 지침

- 문서 번호: TEC-005
- 상태: 현행
- 시행일: 2025-08-01

> 이 문서는 과제 시연을 위해 AI로 생성한 가상 회사의 문서입니다.

## 1. 목적

이 지침은 모음보드 운영 환경(서버, 데이터베이스, 관리 콘솔)에 대한 접근 권한을 최소한으로 부여하고, 부여된 권한을 주기적으로 검토하기 위한 기준을 정한다.

## 2. 기본 원칙

1. **최소 권한**: 업무 수행에 꼭 필요한 범위의 권한만 부여한다.
2. **역할 기반**: 개인이 아니라 역할 단위로 권한 세트를 정의하고 부여한다.
3. **기록**: 모든 접근과 권한 변경은 감사 로그에 남긴다.
4. **다중 인증**: 운영 환경 접근에는 다중 인증(MFA)을 필수로 적용한다.

## 3. 권한 등급

| 등급 | 허용 범위 | 부여 대상 |
| --- | --- | --- |
| 읽기 | 로그, 지표 조회 | 개발 조직 전체 |
| 운영 | 서비스 재시작, 설정 변경 | 플랫폼운영팀, 당직자 |
| 데이터 | 운영 데이터베이스 조회 | 승인된 담당자 |
| 관리자 | 권한 부여, 인프라 변경 | 플랫폼운영팀 책임자 |

## 4. 권한 신청 절차

1. 신청자는 사내 티켓 시스템에서 필요한 권한 등급, 대상 시스템, 사용 기간, 사유를 기재해 신청한다.
2. 소속 팀장이 1차 승인하고, 플랫폼운영팀이 2차 승인 후 권한을 부여한다.
3. 데이터 등급 권한은 정보보호 담당 부서의 추가 승인이 필요하다.

## 5. 임시 권한

1. 장애 대응이나 일회성 작업을 위한 임시 권한은 최대 8시간 동안 유효하다.
2. 임시 권한은 만료 시 자동 회수되며, 연장이 필요하면 다시 신청한다.
3. 당직자는 장애 대응 중 긴급 권한 상승 기능을 사용할 수 있으며, 사용 후 24시간 이내에 사유를 티켓에 기록한다.

## 6. 정기 검토

1. 플랫폼운영팀은 분기마다 전체 권한 보유 현황을 추출해 각 팀장에게 검토를 요청한다.
2. 팀장은 2주 안에 불필요한 권한을 표시하고, 표시된 권한은 즉시 회수한다.
3. 90일 이상 사용하지 않은 권한은 검토 결과와 관계없이 자동 회수한다.

## 7. 입사·이동·퇴사

1. 신규 입사자에게는 읽기 등급만 기본 부여한다.
2. 부서 이동 시 기존 권한은 이동일에 모두 회수하고 새 역할에 맞춰 다시 신청한다.
3. 퇴사자의 계정과 권한은 퇴사일 업무 종료 시각에 일괄 비활성화한다. 인사팀은 퇴사 일정을 3영업일 전까지 플랫폼운영팀에 통보한다.

## 8. 공용 계정 금지

여러 사람이 함께 쓰는 공용 계정은 만들지 않는다. 불가피하게 시스템 계정이 필요한 경우 비밀값을 비밀 관리 저장소에 보관하고, 사람이 직접 로그인하지 않도록 한다.

## 9. 위반 시 조치

권한을 공유하거나 승인 없이 데이터를 반출한 경우 즉시 권한을 회수하고, 정보보호 담당 부서의 조사 결과에 따라 징계 절차를 진행한다.
