# 장애 대응 절차

- 문서 번호: TEC-003
- 상태: 현행
- 시행일: 2025-06-01

> 이 문서는 과제 시연을 위해 AI로 생성한 가상 회사의 문서입니다.

## 1. 목적

이 절차는 모음보드 서비스에 장애가 발생했을 때 신속하게 영향을 줄이고, 고객과 내부 이해관계자에게 정확한 정보를 전달하며, 재발을 막기 위한 기준을 정한다.

## 2. 장애 등급

| 등급 | 정의 | 대응 착수 목표 | 상황 공유 주기 |
| --- | --- | --- | --- |
| SEV1 | 전체 서비스 중단, 데이터 유실 우려 | 15분 이내 | 30분마다 |
| SEV2 | 주요 기능 장애, 다수 고객 영향 | 30분 이내 | 1시간마다 |
| SEV3 | 일부 기능 저하, 우회 방법 존재 | 4시간 이내 | 필요 시 |
| SEV4 | 경미한 오류, 고객 영향 거의 없음 | 다음 영업일 | 해당 없음 |

등급은 최초 인지자가 임시로 정하고, 장애 책임자가 확인 후 조정한다.

## 3. 당직 체계

1. 플랫폼운영팀과 각 개발팀은 주 단위로 당직자를 지정한다.
2. 당직자는 알림 수신 후 5분 이내에 확인 응답을 해야 한다.
3. 당직자가 10분 이내에 응답하지 않으면 다음 순번 당직자와 팀장에게 자동으로 호출이 넘어간다.
4. 당직 근무에는 당직 수당을 지급하며, 야간 출동 시 다음 날 오전 근무를 면제할 수 있다.

## 4. 대응 절차

1. **인지**: 모니터링 알림, 고객 문의, 내부 제보로 장애를 인지하면 장애 채널에 즉시 등록한다.
2. **책임자 지정**: SEV1·SEV2는 장애 책임자를 지정하고, 책임자가 대응 인력과 역할을 배분한다.
3. **영향 파악**: 영향받는 기능, 고객 범위, 시작 시각을 파악해 장애 채널에 기록한다.
4. **완화**: 롤백, 트래픽 차단, 기능 끄기 등 영향을 줄이는 조치를 원인 분석보다 우선한다.
5. **공유**: 상황 공유 주기에 맞춰 내부 공지와 고객 공지(상태 페이지)를 갱신한다.
6. **종료**: 지표가 정상으로 돌아오고 30분 이상 유지되면 책임자가 종료를 선언한다.

## 5. 고객 공지

1. SEV1·SEV2 장애는 인지 후 30분 이내에 상태 페이지에 첫 공지를 게시한다.
2. 공지 문안은 고객지원팀이 작성하고 장애 책임자가 확인한다.
3. 엔터프라이즈 고객에게는 담당 매니저가 별도로 연락한다.

## 6. 사후 회고

1. SEV1·SEV2 장애는 종료 후 5영업일 이내에 회고 문서를 작성한다.
2. 회고는 개인의 잘못을 묻지 않는 방식으로 진행하며, 타임라인, 근본 원인, 재발 방지 조치를 포함한다.
3. 재발 방지 조치는 담당 팀과 완료 기한을 지정해 추적한다.
4. 회고 문서는 사내 위키의 장애 기록 공간에 보관한다.

## 7. 훈련

플랫폼운영팀은 반기마다 장애 모의 훈련을 실시해 당직 호출, 롤백, 고객 공지 절차를 점검한다.

## 8. 기록과 보고

장애 책임자는 장애 채널에 남은 기록을 바탕으로 매월 장애 현황을 정리해 경영진에게 보고한다. 보고에는 등급별 발생 건수, 평균 대응 착수 시간, 평균 복구 시간, 재발 방지 조치 완료율을 포함한다. 같은 원인의 장애가 분기 안에 두 번 이상 발생하면 별도 개선 과제로 등록한다.
