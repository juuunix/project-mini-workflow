# 서비스 배포 절차

- 문서 번호: TEC-002
- 상태: 현행
- 시행일: 2025-05-01

> 이 문서는 과제 시연을 위해 AI로 생성한 가상 회사의 문서입니다.

## 1. 목적

이 문서는 모음보드 서비스를 운영 환경에 배포할 때 따라야 할 절차와 승인 기준, 롤백 기준을 정한다. 모든 개발 조직과 플랫폼운영팀에 적용한다.

## 2. 배포 원칙

1. 운영 배포는 `main` 브랜치에 병합된 커밋만 대상으로 한다.
2. 모든 배포는 CI 파이프라인을 통해서만 수행하며, 서버에 직접 접속해 파일을 바꾸는 방식은 금지한다.
3. 배포는 카나리 방식으로 단계적으로 진행한다.
4. 배포 이력은 배포 대시보드에 자동 기록되며, 수동 배포가 불가피한 경우에도 사후에 기록을 남긴다.

## 3. 배포 가능 시간

| 구분 | 기준 |
| --- | --- |
| 정기 배포 | 화요일 ~ 목요일 10:00 ~ 16:00 |
| 배포 금지 | 금요일, 공휴일 전날, 연말 동결 기간(12월 20일 ~ 1월 3일) |
| 긴급 배포 | 장애 대응 목적에 한해 상시 가능, 당직 책임자 승인 필요 |

## 4. 배포 전 점검

1. 풀 리퀘스트는 리뷰어 2명 이상의 승인을 받아야 병합할 수 있다.
2. 단위 테스트와 통합 테스트가 모두 통과해야 한다.
3. 데이터베이스 스키마 변경이 포함된 경우 사전에 플랫폼운영팀의 검토를 받고, 되돌리기 스크립트를 함께 준비한다.
4. 스테이징 환경에 먼저 배포하고 기능 점검 체크리스트를 완료한다.

## 5. 단계별 배포

| 단계 | 트래픽 비율 | 관찰 시간 | 진행 조건 |
| --- | --- | --- | --- |
| 1단계 | 10% | 15분 | 오류율 0.5% 이하 |
| 2단계 | 50% | 15분 | 오류율 0.5% 이하, 응답 지연 증가 20% 이내 |
| 3단계 | 100% | 30분 | 주요 지표 정상 유지 |

각 단계에서 배포 담당자는 대시보드의 오류율, 응답 시간, CPU 사용률을 확인하고 배포 채널에 결과를 남긴다.

## 6. 롤백 기준

1. 오류율이 1%를 넘거나 응답 시간이 평소 대비 50% 이상 늘어나면 즉시 롤백한다.
2. 롤백은 배포 대시보드의 "이전 버전으로 되돌리기" 기능을 사용하며, 결정 후 5분 이내에 완료해야 한다.
3. 롤백 후에는 장애 대응 절차(TEC-003)에 따라 상황을 공유하고 원인을 분석한다.

## 7. 배포 후 조치

1. 배포 담당자는 배포 완료 후 1시간 동안 모니터링 알림에 대응할 수 있어야 한다.
2. 사용자에게 보이는 변경이 있는 경우 고객지원팀에 변경 내용을 미리 전달한다.
3. 릴리스 노트는 배포 당일 사내 위키에 게시한다.

## 8. 책임

| 역할 | 책임 |
| --- | --- |
| 배포 담당자 | 배포 실행, 단계별 확인, 롤백 결정 |
| 리뷰어 | 코드 품질과 위험 요소 검토 |
| 플랫폼운영팀 | 파이프라인 운영, 긴급 배포 승인 지원 |

## 9. 예외 처리

이 절차를 따르기 어려운 특수한 배포(대규모 데이터 이전, 인프라 교체 등)는 최소 1주 전에 플랫폼운영팀과 작업 계획을 검토한다. 검토 결과에 따라 배포 시간, 단계 비율, 관찰 시간을 조정할 수 있으며, 조정 내용은 작업 계획서에 남긴다.
