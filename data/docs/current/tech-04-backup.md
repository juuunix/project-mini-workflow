# 데이터 백업 및 복구 정책

- 문서 번호: TEC-004
- 상태: 현행
- 시행일: 2025-01-15

> 이 문서는 과제 시연을 위해 AI로 생성한 가상 회사의 문서입니다.

## 1. 목적

이 정책은 모음보드 서비스의 고객 데이터와 운영 데이터를 안전하게 보존하고, 장애나 사고 발생 시 정해진 시간 안에 복구할 수 있도록 백업과 복구 기준을 정한다.

## 2. 적용 대상

| 대상 | 설명 |
| --- | --- |
| 서비스 데이터베이스 | 보드, 카드, 멤버, 결제 정보 |
| 파일 저장소 | 고객이 업로드한 첨부 파일 |
| 설정 저장소 | 서비스 설정, 인프라 구성 코드 |
| 감사 로그 | 관리자 활동 기록, 접근 기록 |

## 3. 백업 주기와 보존 기간

| 구분 | 주기 | 보존 기간 |
| --- | --- | --- |
| 전체 백업 | 매일 03:00 | 35일 |
| 증분 백업 | 1시간마다 | 7일 |
| 트랜잭션 로그 | 실시간 | 7일 |
| 월말 보관 백업 | 매월 마지막 날 | 1년 |
| 감사 로그 | 실시간 | 3년 |

## 4. 복구 목표

| 항목 | 목표 |
| --- | --- |
| 복구 시점 목표(RPO) | 1시간 |
| 복구 시간 목표(RTO) | 4시간 |
| 단일 고객 데이터 복원 | 요청 접수 후 2영업일 |

## 5. 저장 위치와 보호

1. 백업은 운영 데이터센터와 다른 지역의 저장소에 이중으로 보관한다.
2. 모든 백업은 저장 전에 암호화하며, 암호화 키는 별도의 키 관리 체계로 관리한다.
3. 백업 저장소에 대한 삭제 권한은 플랫폼운영팀 책임자 2명의 동시 승인으로만 행사할 수 있다.
4. 백업 저장소는 운영 계정과 분리된 계정에서 관리한다.

## 6. 백업 점검

1. 백업 작업의 성공 여부는 매일 자동으로 점검하고, 실패 시 당직자에게 알림을 보낸다.
2. 백업 실패가 2회 연속 발생하면 SEV3 장애로 등록해 처리한다.
3. 플랫폼운영팀은 매주 백업 용량과 소요 시간 추이를 검토한다.

## 7. 복구 훈련

1. 분기마다 1회 이상 스테이징 환경에서 전체 복구 훈련을 실시한다.
2. 훈련 결과는 실제 복구 소요 시간, 데이터 정합성 점검 결과, 개선 사항을 포함해 기록한다.
3. 훈련에서 RTO를 넘긴 경우 1개월 안에 개선 계획을 수립한다.

## 8. 고객 요청에 따른 복원

1. 고객이 실수로 삭제한 보드의 복원 요청은 고객지원팀이 접수한다.
2. 삭제 후 30일 이내 데이터는 휴지통 기능으로 고객이 직접 복원할 수 있다.
3. 휴지통 보관 기간이 지난 데이터는 백업 보존 기간 안에서만 복원을 검토하며, 엔터프라이즈 요금제 고객에게 우선 제공한다.

## 9. 책임

플랫폼운영팀이 이 정책의 운영과 점검을 책임지며, 정보보호 담당 부서가 연 1회 준수 여부를 감사한다.

## 10. 백업 데이터 접근

백업 데이터를 열람하거나 복원하려면 운영 환경 접근 권한 관리 지침(TEC-005)의 데이터 등급 권한이 필요하다. 복원 작업은 두 사람이 함께 진행하고, 작업 시작과 종료 시각, 복원 범위를 작업 기록에 남긴다.
