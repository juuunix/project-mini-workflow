# 문서 검색 방식 비교

## 비교 목적

문서 검색 노드는 현행 문서를 먼저 검색하고, 현행 문서에 답이 없을 때만 보관 문서를 검색합니다. 그래서 검색 방식은 문서의 순위를 매기는 것만이 아니라, 검색된 문서가 질문과 관련 있는지를 가릴 수 있어야 합니다. 이 실험은 한국어 문서를 나누는 방식(토크나이저), BM25 구현(엔진), 검색된 문서가 질문과 관련 있는지 가리는 방식(판정)을 같은 질문으로 비교합니다.

## 데이터셋 구성

### 문서

`data/docs/`의 문서 30개를 그대로 사용합니다. 현행 문서 15개(`current/`)와 보관 문서 15개(`archive/`)이며, 보관 문서는 현행 문서의 개정 전판과 폐지·종료된 제도의 문서로 이루어져 있습니다.

### 질문

주제 20개를 다섯 유형으로 나누고, 주제마다 세 말투로 써서 질문 60개를 만들었습니다. 질문과 정답은 `queries.py`에 있습니다.

| 유형 | 뜻 | 기대 동작 | 주제 수 | 예 |
| --- | --- | --- | --- | --- |
| A | 현행과 보관(개정 전판)에 모두 있는 주제 | 현행에서 찾는다 | 5 | 연차휴가 이월은 최대 며칠까지 가능한가요? |
| B | 현행에만 있는 주제 | 현행에서 찾는다 | 5 | 교육비 지원 한도는 얼마인가요? |
| C | 보관에만 있는 폐지·종료 제도 | 현행 0건 → 보관에서 찾는다 | 4 | 프리패스 이용권 잔여 쿠폰은 어떻게 관리하나요? |
| D | 폐지 제도 이름에 현행 문서에도 있는 흔한 말("호출 한도", "롤백", "이월")을 섞은 주제 | 현행 0건 → 보관에서 찾는다 | 4 | 헤르메스 API 호출 한도는 얼마인가요? |
| E | 어느 문서에도 없는 내용 | 현행 0건, 보관 0건 | 2 | 사내 주차 지원은 어떻게 받나요? |

| 말투 | 예 |
| --- | --- |
| 존댓말 질문 | 연차휴가 이월은 최대 며칠까지 가능한가요? |
| 구어 | 연차 이월 며칠까지 돼? |
| 키워드 | 연차휴가 이월 일수 |

### 검색 순서와 채점

질문마다 현행 문서를 검색하고, 판정을 통과한 문서가 없으면 보관 문서를 검색합니다. 통과한 문서는 BM25 점수 순으로 세웁니다.

Hit@1은 정답 문서를 1위로 찾은 질문 수입니다. 현행 문서가 정답인데 보관에서 찾았다면, 비슷한 문서가 1위여도 틀린 것으로 봅니다. 어느 문서에도 답이 없는 질문은 아무것도 찾지 않아야 맞습니다. Hit@3은 정답 문서가 3위 안에 있는 질문 수입니다.

## v1

### 후보

| 축 | 후보 | 내용 |
| --- | --- | --- |
| 토크나이저 | `words` | 공백과 문장부호로 나눈 단어. 조사가 붙은 채로 비교하는 기준선 |
| | `bigrams` | 단어마다 2글자씩 겹쳐 나눈 조각 |
| | `kiwi-all` | 형태소 분석기 Kiwi의 형태소 전체 |
| | `kiwi-content` | Kiwi 형태소 중 명사, 동사, 형용사, 어근, 외국어, 숫자만 |
| 엔진 | `rank-bm25` | `BM25Okapi`. NumPy만 필요 |
| | `bm25s` | SciPy 희소 행렬 기반 구현 |
| | `sqlite-fts5` | 표준 라이브러리 `sqlite3`의 전문 검색. 서버 없이 메모리에서 동작 |
| 판정 | `any-overlap` | 점수가 0보다 크면, 즉 질문의 토큰이 하나라도 들어 있으면 관련 있다고 본다. 기준선 |
| | `score-threshold` | 점수가 기준값 이상이면 관련 있다고 본다 |

엔진에는 미리 토큰화한 문서와 질문을 넘깁니다. SQLite에는 토큰을 공백으로 이어 넣어, 토큰을 나누는 일은 모두 토크나이저가 맡도록 했습니다.

`score-threshold`의 기준값은 실제로 나온 점수를 하나씩 기준값으로 넣어 보고, 질문 60개에서 Hit@1이 가장 높은 값을 골랐습니다. 시험 질문에 맞춘 값이므로 이 방식이 낼 수 있는 최대치입니다.

### 결과 요약

전체 표는 `v1/results/summary.md`, 질문별 결과는 `v1/results/details/`에 있습니다.

| 토크나이저 | `any-overlap` Hit@1 | `score-threshold` Hit@1 (rank-bm25 / bm25s / sqlite-fts5) |
| --- | --- | --- |
| `words` | 29~30 | 44 / 44 / 44 |
| `bigrams` | 22~23 | 40 / 39 / 38 |
| `kiwi-all` | 23~24 | 36 / 41 / 37 |
| `kiwi-content` | 29~30 | 43 / 45 / 41 |

- `any-overlap`은 보관으로 넘어가야 할 질문(C·D 24개) 중 0~4개만 넘겼습니다. 흔한 단어("API", "롤백", "이월")가 들어 있는 현행 문서가 거의 항상 있었기 때문입니다. `score-threshold`는 C·D를 15~22개 보관으로 보냈지만, 현행에서 찾아야 할 질문(A·B 30개)도 10~14개를 현행에서 놓쳤습니다(대부분 보관에서도 찾지 못해 0건으로 끝났습니다).
- 엔진 사이의 차이는 질문 몇 개 수준이었습니다.

BM25 점수만으로는 흔한 단어가 우연히 겹친 문서와 실제로 답이 있는 문서를 가를 수 없었습니다. 그래서 v2에서는 점수 외의 정보를 쓰는 판정 방식을 추가했습니다.

## v2

### 후보

토크나이저와 엔진은 v1과 같습니다. 판정 방식 네 가지를 추가했고, 비교를 위해 v1의 판정 두 가지도 함께 실행합니다.

| 판정 | 내용 |
| --- | --- |
| `rare-word` | 질문의 토큰 중 문서 30개에서 가장 적게 나오는 토큰(예: "헤르메스")이 들어 있는 문서만 관련 있다고 본다. 어느 문서에도 없는 토큰은 고르지 않는다 |
| `rare-word-bigrams` | 위와 같지만 고른 토큰을 2글자 조각으로 나눠, 조각이 모두 들어 있는 문서만 관련 있다고 본다. 문서에서 그 단어에 조사가 붙어 있어도 통과한다(질문의 "헤르메스"는 문서의 "헤르메스는"과 맞는다). 질문 쪽 토큰에 붙은 조사는 조각에 남는다 |
| `title-match` | 질문의 토큰이 문서 제목에 들어 있는 문서만 관련 있다고 본다 |
| `score-ratio` | 1위 점수가 2위 점수의 기준값 배 이상일 때만 관련 있다고 본다. 기준값은 `score-threshold`와 같은 방법으로 골랐다 |

판정은 문서를 통과시킬지만 정하고, 통과한 문서의 순서는 v1과 같이 BM25 점수로 정합니다.

### 결과 요약

전체 표는 `v2/results/summary.md`, 질문별 결과는 `v2/results/details/`에 있습니다. 표의 숫자는 질문 60개 중 Hit@1입니다. 엔진 세 개로 각각 돌린 결과가 다르면 `42~43`처럼 가장 낮은 값과 가장 높은 값을 적었습니다.

| 토크나이저 | `rare-word` | `rare-word-bigrams` | `title-match` | `score-ratio` |
| --- | --- | --- | --- | --- |
| `words` | 42~43 | 39~40 | 42 | 34 |
| `bigrams` | 34~35 | 34~35 | 50 | 34~36 |
| `kiwi-all` | 38~39 | 38~39 | 46 | 33~34 |
| `kiwi-content` | 46~47 | 46~47 | 46 | 37~39 |

- 토큰을 직접 비교하는 세 판정은 현행에서 찾아야 할 질문(A·B 30개)을 현행에서 놓치는 경우를 대부분 0~2개로 줄였습니다(`words` + `title-match`만 9개). v1의 `score-threshold`는 10~14개였습니다. 점수만 쓰는 `score-ratio`는 3~15개로 조합에 따라 크게 흔들렸습니다.
- `bigrams` + `title-match`는 Hit@1이 50으로 가장 높았습니다. 다만 흔한 단어가 현행 문서 제목에 있으면 현행에서 멈췄습니다(예: "헤르메스 API 호출 한도"의 "API").

## 구성

질문, 토크나이저, 엔진, 실행 과정은 모든 차수가 함께 쓰고, 판정 방식만 차수별 폴더에 둡니다.

| 파일 | 내용 |
| --- | --- |
| `queries.py` | 질문 60개와 정답 |
| `tokenizers.py` | 토크나이저 |
| `engines.py` | BM25 엔진 |
| `runner.py` | 검색 순서, 채점, 결과 표 작성 |
| `v1/`, `v2/` | 차수별 판정 방식(`judges.py`), 실행 파일(`compare.py`), 결과(`results/`) |

## 실행 방법

저장소 루트에서 실행합니다. 인자로 토크나이저나 엔진 하나만 고를 수 있습니다.

```text
uv run --project experiments/rag-search --locked python experiments/rag-search/v1/compare.py
uv run --project experiments/rag-search --locked python experiments/rag-search/v1/compare.py --tokenizer bigrams --engine sqlite-fts5
```

전체 결과는 `v1/results/summary.md`, 조합별 질문 결과는 `v1/results/details/`에 저장됩니다. v2도 같은 방식입니다.
